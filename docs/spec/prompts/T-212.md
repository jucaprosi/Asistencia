## Requisitos
**RF-PMS-02 — Implementaciones.** Una implementación por proveedor en archivos privados de la sala (`fake_internal.py`, `plataforma_internal.py`); se activa una sola por configuración. *Criterios:* (a) cambiar de proveedor es un cambio en `config_pms_conector.yaml`, sin tocar `agente` ni `herramientas_glamping`; (b) las escrituras están desactivadas por defecto y se habilitan de forma explícita por operación (patrón *read-mostly* del informe §5.4). *Árbitro:* `tests/pms_conector/test_seleccion_proveedor.py`.
**RF-PMS-07 — Calendario y tarifas propios.** La disponibilidad sale de `pms.noches_ocupadas` y el precio de `pms.tarifas_noche`. *Criterios:* (a) una noche sin tarifa no se ofrece; (b) dos reservas simultáneas no ocupan la misma noche (`INV_SIN_DOBLE_RESERVA`); (c) se respeta el mínimo de noches. *Árbitro:* `tests/pms_conector/test_calendario.py`.
**RF-PMS-08 — Mantenimiento del calendario.** El equipo carga tarifas y fechas en el panel. El anfitrión bloquea o libera fechas por WhatsApp con `actualizar_calendario`. *Criterios:* (a) el anfitrión solo cambia sus unidades (`INV_AISLAMIENTO_ANFITRION`); (b) liberar nunca toca una noche reservada; (c) cada cambio queda en el audit log. *Árbitro:* `tests/pms_conector/test_calendario.py`.

## Tablas de esta sala
```sql
CREATE TABLE pms.propiedades (
  propiedad_id     text PRIMARY KEY,
  tipo             text NOT NULL CHECK (tipo IN ('glamping','cabana','casa','departamento','habitacion','hostal','hosteria','hotel','hacienda','otro')),
  nombre           text NOT NULL,
  zona_id          text NOT NULL,
  direccion        text NOT NULL,
  pms_ref          text,
  prompt_variante  text NOT NULL CHECK (prompt_variante IN ('glamping','departamentos','hospedaje')),
  activa           boolean NOT NULL DEFAULT true
);

CREATE TABLE pms.unidades (
  unidad_id        text PRIMARY KEY,
  propiedad_id     text NOT NULL REFERENCES pms.propiedades(propiedad_id),
  nombre           text NOT NULL,
  capacidad        integer NOT NULL CHECK (capacidad >= 1),
  edificio         text,
  piso             text,
  acceso_ref       text,                              -- token de bóveda; nunca el código en claro
  wifi_ref         text
);

CREATE TABLE pms.reservas_ref (
  codigo_reserva   text PRIMARY KEY,
  propiedad_id     text NOT NULL REFERENCES pms.propiedades(propiedad_id),
  unidad_id        text NOT NULL REFERENCES pms.unidades(unidad_id),
  huesped_id       uuid NOT NULL,
  desde            date NOT NULL,
  hasta            date NOT NULL,
  estado           text NOT NULL CHECK (estado IN ('preliminar','confirmada','cancelada','expirada','completada')),
  expira_en        timestamptz,
  pms_ref          text,
  actualizada      timestamptz NOT NULL DEFAULT now(),
  CHECK (hasta > desde)
);

CREATE TABLE pms.tarifas_noche (
  unidad_id        text NOT NULL REFERENCES pms.unidades(unidad_id),
  noche            date NOT NULL,
  precio           numeric(12,2) NOT NULL CHECK (precio >= 0),
  minimo_noches    integer NOT NULL DEFAULT 1 CHECK (minimo_noches >= 1),
  PRIMARY KEY (unidad_id, noche)
);

CREATE TABLE pms.noches_ocupadas (
  unidad_id        text NOT NULL REFERENCES pms.unidades(unidad_id),
  noche            date NOT NULL,
  origen           text NOT NULL CHECK (origen IN ('reserva','bloqueo')),
  codigo_reserva   text REFERENCES pms.reservas_ref(codigo_reserva),
  PRIMARY KEY (unidad_id, noche),
  CHECK ((origen = 'reserva') = (codigo_reserva IS NOT NULL))
);

CREATE TABLE pms.incidencias (
  incidencia_id    text PRIMARY KEY CHECK (incidencia_id ~ '^I-[0-9]{4}-[0-9]{4,}$'),
  propiedad_id     text NOT NULL REFERENCES pms.propiedades(propiedad_id),
  unidad_id        text REFERENCES pms.unidades(unidad_id),
  codigo_reserva   text,
  categoria        text NOT NULL CHECK (categoria IN ('agua','electricidad','limpieza','acceso','seguridad','ruido','wifi','otra')),
  prioridad        text NOT NULL CHECK (prioridad IN ('baja','media','alta','critica')),
  estado           text NOT NULL DEFAULT 'abierta' CHECK (estado IN ('abierta','en_curso','resuelta')),
  descripcion_token text NOT NULL,
  gestor_id        uuid,
  creada           timestamptz NOT NULL DEFAULT now(),
  resuelta_en      timestamptz,
  resuelta_por     uuid,
  nota             text,
  CHECK (categoria NOT IN ('acceso','seguridad') OR prioridad = 'critica')
);

CREATE TABLE pms.idempotencia (
  clave            uuid PRIMARY KEY,
  operacion        text NOT NULL,
  resultado_json   jsonb NOT NULL,
  creado_en        timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE pms.secuencia_incidencias (
  anio             integer PRIMARY KEY,
  ultimo           integer NOT NULL DEFAULT 0
);
```

## Invariantes
| Código | Predicado | Mecanismo obligatorio |
| :--- | :--- | :--- |
| `INV_AISLAMIENTO_ANFITRION` | `actor = anfitrion ⇒ anfitrion_id(fila) = identidad(actor)` | `anfitrion_id` sale de la identidad verificada; RLS con `FORCE` en `anfitriones.solicitudes`. |
| `INV_ESCRITURA_PMS_EXPLICITA` | `escritura(op) ⇒ habilitada(op)`; `reintento(op) ⇒ ∃ clave_idempotencia(op)` | Lista por operación en configuración; `pms.idempotencia` con `clave` única. |
| `INV_SECRETO_OPERATIVO` | `∀ s ∈ secretos : s ∉ payload ∪ historial ∧ (enviado(s, r) ⇒ titular(r))` | Marcador `[[SECRETO:id]]` resuelto solo en la salida. |
| `INV_SIN_CLIENTES_OTA` | `∀ i ∈ imports : i ∉ clientes_OTA` | Revisión de imports y manifiestos. |
| `INV_SIN_DOBLE_RESERVA` | `∀ u, n : ∣ocupaciones(u, n)∣ ≤ 1` | `PRIMARY KEY (unidad_id, noche)` en `pms.noches_ocupadas`; todas las noches se insertan en una transacción. |
| `INV_TICKET_UNICO` | `∀ año : tickets(año) = {1, …, n}` sin repetidos | `UPDATE ... SET ultimo = ultimo + 1 ... RETURNING ultimo` en la misma transacción del `INSERT`; un `ROLLBACK` no deja huecos. Prohibidas las `SEQUENCE`. |
