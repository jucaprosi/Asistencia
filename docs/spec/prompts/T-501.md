## Requisitos
**RF-COM-01 — Reglas versionadas.** Reglas de comisión por vendedor, producto/propiedad y período, con porcentaje o monto fijo, escalones por volumen y vigencia. *Criterios:* (a) cada regla tiene `version`, `vigente_desde`, `vigente_hasta`; (b) `calcular(venta, vendedor, fecha)` elige la regla vigente a la fecha de la venta, no a la fecha del cálculo; (c) la tasa escalonada usa el acumulado validado del vendedor en el período antes de esta venta, guardado en `base_acumulada`; (d) sin regla aplicable falla con `SinReglaVigente` y la venta sigue `por_validar`; (e) USD, dos decimales, `ROUND_HALF_UP`. *Árbitro:* `tests/comisiones/test_reglas.py`.
**RF-COM-02 — Cierre de período.** Un período (mes por defecto) se cierra y queda inmutable; las correcciones posteriores generan ajustes en el período siguiente. *Criterios:* (a) no se puede modificar una comisión de un período cerrado; (b) el cierre produce un resumen por vendedor con total, número de ventas y ajustes; (c) el período es el mes de `fecha_venta` en `America/Guayaquil`, y si ya cerró la comisión entra al período abierto más antiguo con `periodo_origen`. *Árbitro:* `tests/comisiones/test_cierre_periodo.py`.
**RF-COM-04 — Efectos de la anulación.** Anular una venta con comisión crea un ajuste negativo en el período abierto. *Criterios:* (a) la comisión original no se altera; (b) si la venta se publicó, sale el evento `venta_anulada`; (c) una reserva cancelada no anula sola: lo decide el administrador. *Árbitro:* `tests/comisiones/test_anulacion.py`.

## Tablas de esta sala
```sql
CREATE TABLE comisiones.reglas (
  regla_id         text NOT NULL,
  version          integer NOT NULL CHECK (version >= 1),
  vendedor_id      uuid,
  propiedad_id     text,
  producto_patron  text,
  tipo             text NOT NULL CHECK (tipo IN ('porcentaje','fijo','escalonada')),
  valor            numeric(12,4),
  escalones        jsonb NOT NULL DEFAULT '[]',
  vigente_desde    date NOT NULL,
  vigente_hasta    date,
  creada_por       text NOT NULL,
  creada_en        timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (regla_id, version),
  CHECK (vigente_hasta IS NULL OR vigente_hasta >= vigente_desde)
);

CREATE TABLE comisiones.periodos (
  periodo_id       text PRIMARY KEY CHECK (periodo_id ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),
  cerrado_en       timestamptz,
  cerrado_por      text,
  resumen_json     jsonb
);

CREATE TABLE comisiones.comisiones (
  comision_id      uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  venta_id         uuid NOT NULL,
  regla_id         text NOT NULL,
  regla_version    integer NOT NULL,
  monto            numeric(12,2) NOT NULL,
  base_acumulada   numeric(12,2) NOT NULL DEFAULT 0 CHECK (base_acumulada >= 0),
  periodo_id       text NOT NULL REFERENCES comisiones.periodos(periodo_id),
  periodo_origen   text NOT NULL,
  estado           text NOT NULL CHECK (estado IN ('estimada','fijada','pagada','ajustada')),
  ajuste_de        uuid REFERENCES comisiones.comisiones(comision_id),
  motivo           text,
  FOREIGN KEY (regla_id, regla_version) REFERENCES comisiones.reglas(regla_id, version),
  CHECK (estado <> 'ajustada' OR ajuste_de IS NOT NULL),
  CHECK (estado = 'ajustada' OR monto >= 0)
);
```
