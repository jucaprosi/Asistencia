## Requisitos
**RF-ANF-01 — Alta de anfitrión.** El administrador registra al anfitrión con versión de términos aceptada y porcentaje pactado. *Criterios:* (a) sin términos no hay alta; (b) el teléfono se guarda como token; (c) cada cambio queda en el audit log. *Árbitro:* `tests/anfitriones/test_publicacion.py`.
**RF-ANF-02 — Publicación revisada.** El equipo pasa cada hospedaje por `borrador`, `publicado` y `pausado`. *Criterios:* (a) publicar exige actor y fecha; (b) el anfitrión no publica por sí mismo. *Árbitro:* `tests/anfitriones/test_publicacion.py`.
**RF-ANF-04 — Solicitud de reserva.** Una reserva preliminar genera una solicitud con código `PL-`. *Criterios:* (a) fechas y total salen del PMS, nunca del modelo; (b) el porcentaje queda congelado; (c) el anfitrión recibe la plantilla con vigencia de 24 horas. *Árbitro:* `tests/anfitriones/test_solicitudes.py`.
**RF-ANF-05 — Respuesta del anfitrión.** Confirma o rechaza por WhatsApp. *Criterios:* (a) el contacto se entrega solo al confirmar (`INV_CONTACTO_TRAS_CONFIRMAR`); (b) sin respuesta la solicitud expira y el huésped recibe otras opciones; (c) nadie responde por otro anfitrión (`INV_AISLAMIENTO_ANFITRION`). *Árbitro:* `tests/anfitriones/test_solicitudes.py`, `tests/anfitriones/test_aislamiento.py`.
**RF-ANF-06 — Resultado de la estadía.** El anfitrión reporta `cancelada` o `no_show` hasta 3 días después de la salida. *Criterios:* (a) sin reporte pasa a `completada`; (b) `cancelada` y `no_show` no generan comisión. *Árbitro:* `tests/anfitriones/test_resultado.py`.
| US-19 | transversal | Como anfitrión, quiero confirmar cada solicitud por WhatsApp para recibir reservas sin atender cada consulta. | [`anfitriones.feature`](../../spec/features/anfitriones.feature) |

## Tablas de esta sala
```sql
CREATE TABLE anfitriones.anfitriones (
  anfitrion_id        uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  nombre_comercial    text NOT NULL,
  telefono_token      text NOT NULL UNIQUE,
  comision_porcentaje numeric(5,2) NOT NULL CHECK (comision_porcentaje BETWEEN 0 AND 100),
  terminos_version    text NOT NULL,
  terminos_aceptados_en timestamptz NOT NULL,
  estado              text NOT NULL DEFAULT 'activo' CHECK (estado IN ('activo','suspendido')),
  creado_en           timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE anfitriones.hospedajes (
  propiedad_id     text PRIMARY KEY,
  anfitrion_id     uuid NOT NULL REFERENCES anfitriones.anfitriones (anfitrion_id),
  estado           text NOT NULL DEFAULT 'borrador' CHECK (estado IN ('borrador','publicado','pausado')),
  publicado_por    text,
  publicado_en     timestamptz,
  CHECK (estado <> 'publicado' OR (publicado_por IS NOT NULL AND publicado_en IS NOT NULL))
);

CREATE TABLE anfitriones.solicitudes (
  solicitud        text PRIMARY KEY CHECK (solicitud ~ '^PL-[0-9]{4}-[0-9]{4,}$'),
  codigo_reserva   text NOT NULL UNIQUE,
  propiedad_id     text NOT NULL REFERENCES anfitriones.hospedajes (propiedad_id),
  anfitrion_id     uuid NOT NULL REFERENCES anfitriones.anfitriones (anfitrion_id),
  desde            date NOT NULL,
  hasta            date NOT NULL,
  total            numeric(12,2) NOT NULL CHECK (total >= 0),
  comision_porcentaje numeric(5,2) NOT NULL CHECK (comision_porcentaje BETWEEN 0 AND 100),
  estado           text NOT NULL DEFAULT 'solicitada' CHECK (estado IN ('solicitada','confirmada','rechazada','expirada','cancelada','no_show','completada')),
  vence_en         timestamptz NOT NULL,
  respondida_en    timestamptz,
  creado_en        timestamptz NOT NULL DEFAULT now(),
  CHECK (hasta > desde)
);

CREATE TABLE anfitriones.estados_cuenta (
  estado_cuenta_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  anfitrion_id     uuid NOT NULL REFERENCES anfitriones.anfitriones (anfitrion_id),
  periodo          text NOT NULL CHECK (periodo ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),
  total            numeric(12,2) NOT NULL,
  estado           text NOT NULL DEFAULT 'emitido' CHECK (estado IN ('emitido','pagado','vencido')),
  emitido_en       timestamptz NOT NULL DEFAULT now(),
  vence_en         date NOT NULL,
  pagado_en        timestamptz,
  pago_registrado_por text,
  UNIQUE (anfitrion_id, periodo),
  CHECK (estado <> 'pagado' OR (pagado_en IS NOT NULL AND pago_registrado_por IS NOT NULL))
);

CREATE TABLE anfitriones.lineas_cuenta (
  linea_id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  estado_cuenta_id uuid NOT NULL REFERENCES anfitriones.estados_cuenta (estado_cuenta_id),
  solicitud        text NOT NULL,
  tipo             text NOT NULL DEFAULT 'cargo' CHECK (tipo IN ('cargo','ajuste')),
  base             numeric(12,2) NOT NULL,
  porcentaje       numeric(5,2) NOT NULL,
  comision         numeric(12,2) NOT NULL,
  UNIQUE (solicitud, tipo)
);
```

## Invariantes
| Código | Predicado | Mecanismo obligatorio |
| :--- | :--- | :--- |
| `INV_AISLAMIENTO_ANFITRION` | `actor = anfitrion ⇒ anfitrion_id(fila) = identidad(actor)` | `anfitrion_id` sale de la identidad verificada; RLS con `FORCE` en `anfitriones.solicitudes`. |
| `INV_COMISION_PLATAFORMA_UNICA` | `∀ s : ∣cargos(s)∣ ≤ 1` | `UNIQUE (solicitud, tipo)` en `anfitriones.lineas_cuenta`. |
| `INV_CONTACTO_TRAS_CONFIRMAR` | `contacto_entregado(s) ⇒ estado(s) = confirmada` | El contacto sale solo en la transición a `confirmada`, dentro de `responder_solicitud`. |
| `INV_SOLO_PUBLICADO` | `visible(h) ⇒ estado(h) = publicado ∧ estado(anfitrion(h)) = activo` | La web y el agente leen `anfitriones.publicados()`. |
