## Requisitos
**RF-ARM-08 — Tablero.** Datos agregados: ventas por mes, por vendedor, por propiedad; comisiones validadas y pendientes; exportación CSV por período. *Criterios:* (a) los totales del tablero coinciden al centavo con las comisiones del período, incluidos los ajustes, y con las ventas en `validada`, `publicada` o `no_publicada`; (b) la exportación reproduce exactamente las filas del tablero. **RF-CRM-04 — Manejo de errores del CRM.** Errores tipados: `CRMNoDisponible`, `ContactoDuplicado`, `WebhookRechazado`, `LimiteDeTasa`. *Criterios:* (a) las publicaciones fallidas entran en una cola persistente con *backoff* y se reintentan hasta 24 h; (b) una venta nunca se pierde: queda `no_publicada`, con alerta y reintento manual desde el panel, hasta que el CRM la acepta. *Árbitro:* `tests/crm_conector/test_cola_reintentos.py`.

## Tablas de esta sala
```sql
CREATE TABLE arm.vendedores (
  vendedor_id      uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  telefono_token   text NOT NULL UNIQUE,
  nombre           text NOT NULL,
  activo           boolean NOT NULL DEFAULT true,
  regla_comision_default_id text
);

CREATE TABLE arm.secuencia_tickets (
  anio             integer PRIMARY KEY,
  ultimo           integer NOT NULL DEFAULT 0
);

CREATE TABLE arm.ventas (
  venta_id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  ticket           text NOT NULL UNIQUE CHECK (ticket ~ '^V-[0-9]{4}-[0-9]{4,}$'),
  vendedor_id      uuid NOT NULL REFERENCES arm.vendedores(vendedor_id),
  cliente_token    text,
  telefono_cliente_token text,
  producto         text NOT NULL,
  propiedad_id     text,
  noches           integer CHECK (noches >= 1),
  monto            numeric(12,2) NOT NULL CHECK (monto > 0),
  moneda           text NOT NULL DEFAULT 'USD' CHECK (moneda = 'USD'),
  fecha_venta      date NOT NULL,
  fecha_llegada    date,
  texto_original_token text NOT NULL,
  mensaje_id       text NOT NULL,
  indice_en_mensaje integer NOT NULL DEFAULT 0,
  confianza        numeric(3,2) NOT NULL CHECK (confianza BETWEEN 0 AND 1),
  confianza_campos jsonb NOT NULL DEFAULT '{}',
  huella_duplicado text NOT NULL,
  posible_duplicado_de uuid REFERENCES arm.ventas(venta_id),
  estado           text NOT NULL DEFAULT 'por_validar' CHECK (estado IN ('por_validar','validada','rechazada','publicada','no_publicada','anulada')),
  reserva_ref      text,
  creada           timestamptz NOT NULL DEFAULT now(),
  validada_en      timestamptz,
  actualizada      timestamptz NOT NULL DEFAULT now(),
  UNIQUE (mensaje_id, indice_en_mensaje)
);

CREATE TABLE arm.transiciones (
  transicion_id    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  venta_id         uuid NOT NULL REFERENCES arm.ventas(venta_id),
  de               text NOT NULL,
  a                text NOT NULL,
  actor_id         text NOT NULL,
  rol              text NOT NULL,
  motivo           text,
  instante         timestamptz NOT NULL DEFAULT now(),
  CHECK (a NOT IN ('rechazada','anulada') OR motivo IS NOT NULL),
  CHECK (a <> 'anulada' OR rol = 'administrador')
);

CREATE TABLE arm.configuracion (
  clave            text PRIMARY KEY,
  valor            jsonb NOT NULL,
  cambiado_por     text NOT NULL,
  cambiado_en      timestamptz NOT NULL DEFAULT now()
);
```

## Invariantes
| Código | Predicado | Mecanismo obligatorio |
| :--- | :--- | :--- |
| `INV_COMISION_PROPIA` | `respuesta(q, r) ⇒ vendedor(datos) = vendedor(r)` | `vendedor_id` inyectado por el servidor. |
| `INV_ESTADOS_VENTA` | `(e, e') ∈ transicion(v) ⇒ e' ∈ transiciones[e]` | `UPDATE arm.ventas SET estado = $nuevo WHERE venta_id = $id AND estado = $esperado`: 0 filas es conflicto. Disparador `arm.validar_transicion`. |
| `INV_TICKET_UNICO` | `∀ año : tickets(año) = {1, …, n}` sin repetidos | `UPDATE ... SET ultimo = ultimo + 1 ... RETURNING ultimo` en la misma transacción del `INSERT`; un `ROLLBACK` no deja huecos. Prohibidas las `SEQUENCE`. |
| `INV_VENTA_NO_SE_PIERDE` | `validada(v) ⇒ ◇ publicada(v) ∨ alerta(v)`; `nunca descartada(v)` | Cola persistente en `crm.publicaciones`. |
