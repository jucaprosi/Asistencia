## Requisitos
**RF-ARM-02 — Extracción estructurada.** Claude extrae de texto libre una lista de `VentaExtraida` según [`herramientas.yaml`](../../spec/contratos/herramientas.yaml), con `noches`, `fecha_llegada`, `confianza` y `confianza_campos`; el `vendedor_id` nunca sale del texto. *Criterios:* (a) ≥ 95 % de extracciones correctas sobre `evals/ventas.jsonl` (≥ 60 mensajes reales anonimizados, incluidos mensajes con errores de tipeo, montos con y sin separadores y fechas relativas); (b) si falta un campo obligatorio (`monto`, `producto`), el ARM pregunta al vendedor por el campo exacto en lugar de registrar; (c) un mensaje que no es una venta (saludo, pregunta) no genera registro. *Árbitro:* `scripts/run_evals.py --suite ventas`.
**RF-SEC-05 — Redacción de PII.** Tokeniza nombres, teléfonos, correos, documentos de identidad, tarjetas y direcciones antes de cada llamada al modelo y rehidrata en la respuesta. *Criterios:* (a) ningún número de teléfono ni documento aparece en los *payloads* enviados al modelo (test con captura del cliente HTTP); (b) la rehidratación restituye exactamente el valor original; (c) el historial persistido (RF-AG-06) contiene los tokens, no los valores; (d) teléfono, correo, documento y tarjeta se detectan por reglas con recall de 100 %; (e) nombres y direcciones con recall mínimo de 95 % sobre `evals/pii.jsonl`, 200 casos sintéticos. *Árbitro:* `tests/seguridad/test_pii.py`, `scripts/run_evals.py --suite pii`.

CREATE TABLE arm.vendedores (
  vendedor_id      text PRIMARY KEY DEFAULT gen_random_uuid()::text,
  telefono_token   text NOT NULL UNIQUE,

  regla_comision_default_id text

CREATE TABLE arm.secuencia_tickets (
  anio             integer PRIMARY KEY,
  ultimo           integer NOT NULL DEFAULT 0

CREATE TABLE arm.ventas (
  venta_id         text PRIMARY KEY DEFAULT gen_random_uuid()::text,
  ticket           text NOT NULL UNIQUE CHECK (ticket ~ '^V-[0-9]{4}-[0-9]{4,}$'),
  vendedor_id      text NOT NULL REFERENCES arm.vendedores(vendedor_id),
  cliente_token    text,
  telefono_cliente_token text,
  producto         text NOT NULL,
  propiedad_id     text,
  noches           integer CHECK (noches >= 1),
  monto            numeric(12,2) NOT NULL CHECK (monto > 0),
  moneda           text NOT NULL DEFAULT 'USD' CHECK (moneda = 'USD'),
  fecha_venta      date NOT NULL,
  fecha_llegada    date,
  texto_original_token text NOT NULL,
  mensaje_id       text NOT NULL,
  indice_en_mensaje integer NOT NULL DEFAULT 0,
  confianza        numeric(3,2) NOT NULL CHECK (confianza BETWEEN 0 AND 1),
  confianza_campos jsonb NOT NULL DEFAULT '{}',
  huella_duplicado text NOT NULL,
  posible_duplicado_de text REFERENCES arm.ventas(venta_id),
  estado           text NOT NULL DEFAULT 'por_validar' CHECK (estado IN ('por_validar','validada','rechazada','publicada','no_publicada','anulada')),
  reserva_ref      text,
  creada           timestamptz NOT NULL DEFAULT now(),
  validada_en      timestamptz,
  actualizada      timestamptz NOT NULL DEFAULT now(),
  UNIQUE (mensaje_id, indice_en_mensaje)
);

CREATE TABLE arm.transiciones (
  transicion_id    text PRIMARY KEY DEFAULT gen_random_uuid()::text,
  venta_id         text NOT NULL REFERENCES arm.ventas(venta_id),
  de               text NOT NULL,
  a                text NOT NULL,
  actor_id         text NOT NULL,
  rol              text NOT NULL,
  motivo           text,
  instante         timestamptz NOT NULL DEFAULT now(),
  CHECK (a NOT IN ('rechazada','anulada') OR motivo IS NOT NULL),
  CHECK (a <> 'anulada' OR rol = 'administrador')
);

CREATE TABLE arm.configuracion (
  clave            text PRIMARY KEY,
  valor            jsonb NOT NULL,
  cambiado_por     text NOT NULL,

);

## Invariantes
| Código | Predicado | Mecanismo obligatorio |
| :--- | :--- | :--- |
| `INV_COMISION_PROPIA` | `respuesta(q, r) ⇒ vendedor(datos) = vendedor(r)` | `vendedor_id` inyectado por el servidor. |
| `INV_ESTADOS_VENTA` | `(e, e') ∈ transicion(v) ⇒ e' ∈ transiciones[e]` | `UPDATE arm.ventas SET estado = $nuevo WHERE venta_id = $id AND estado = $esperado`: 0 filas es conflicto. Disparador `arm.validar_transicion`. |
| `INV_PII_FUERA_DEL_MODELO` | `∀ v ∈ PII(m) : v ∉ payload ∪ logs ∪ trazas ∪ historial` | Tokenización antes de cada llamada; rehidratación solo en la salida. |
| `INV_TICKET_UNICO` | `∀ año : tickets(año) = {1, …, n}` sin repetidos | `UPDATE ... SET ultimo = ultimo + 1 ... RETURNING ultimo` en la misma transacción del `INSERT`; un `ROLLBACK` no deja huecos. Prohibidas las `SEQUENCE`. |
| `INV_VENTA_NO_SE_PIERDE` | `validada(v) ⇒ ◇ publicada(v) ∨ alerta(v)`; `nunca descartada(v)` | Cola persistente en `crm.publicaciones`. |
