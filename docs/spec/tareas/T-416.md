## API

No cambia ninguna firma pública: `evaluar` y `evaluar_suite` siguen igual, y `FIRMAS_COMPUERTAS.json` no se toca.

Las dos llamadas pasan a ser:

```python

servicio_agente = AgenteService(cargar_config_agente(), seguridad=SeguridadService())
```

En `evaluar`, si la suite `enrutador` falla, se registra en lugar de callarse:

```python
except Exception as exc:  # noqa: BLE001
    self.log("warning", "evaluacion_fallida", suite="enrutador", tipo=type(exc).__name__)
```

## Reglas

- **R1. Seguridad real.** Las dos construcciones de `AgenteService` para la suite `enrutador` pasan `seguridad=` con una instancia de `SeguridadService`, importada por su compuerta `features.seguridad.seguridad_service`. No se usa un doble.
- **R2. Sin doble por defecto.** T-416 no toca `features/agente/`. El doble nulo lo quita T-407.
- **R3. Falla registrada.** Si la suite `enrutador` lanza una excepción en `evaluar`, queda un registro `evaluacion_fallida` con `suite` y el tipo de la excepción, sin su mensaje, que podría traer datos. Si falla, la clave `enrutador` sigue faltando en el resultado, como hoy; lo que cambia es que ya no hay silencio.
- **R4. Las otras suites no cambian.** `rag`, `ventas` e `inyecciones` conservan su conducta. Si se quiere registrar también sus fallas, va en otra ficha.
- **R5. run_evals no cambia su salida.** `evaluar_suite("enrutador")` sigue devolviendo `APROBADA`, `FALLO_UMBRAL` o `ERROR` con el mismo código de salida.
