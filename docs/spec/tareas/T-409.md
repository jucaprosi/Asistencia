# T-409: espera del reintento de inferencia ante 429 y 5xx (I-1, A4)

> Borrador del Arquitecto ADPA G.I. [b07394], 2026-11-25. Su destino es `docs/spec/tareas/T-409.md`, y entra por un PR de especificación antes del código. Implementa la Enmienda 2 del ADR-0021 (`briefs\2026-11-25_ADR-0021_enmienda2.md`), que tiene que estar aceptada antes de que el PR de código pase a listo.

## Datos

Medido sobre `origin/main c55c529`:

- `features/inferencia/config_inferencia.yaml` tiene hoy `reintentos: 1` y `espera_reintento_s: 0.2`, con el comentario «espera de 0,5x a 1,5x la base».
- `features/inferencia/inferencia_service.py`, en `InferenciaService.generar`, líneas 219 a 262:
  - `espera = espera_base * random.uniform(0.5, 1.5)`;

  - `_reintentable` acepta 429 y de 500 a 599, y lee el código de `exc.code` o de `exc.status_code` (`_codigo_http`).
  - Hoy no se lee ninguna cabecera del error.
  - Si no se reintenta, falla cerrado con `InferenciaNoDisponible(f"proveedor_no_disponible:{type(exc).__name__}")`.
- `tests/inferencia/test_paso4_adr0021.py`:

- **Supuesto:** el SDK `google-genai` expone la respuesta HTTP en `exc.response`, con `headers` de tipo mapeo y sin distinguir mayúsculas. Si no es así, `Retry-After` se ignora y se usa la base, como si la cabecera no viniera.
- **Decidido:** el tope `espera_maxima_s = 5.0` lo aprobó el CTO el 2026-11-25. Con él, el huésped no espera más de 5 s por un reintento dentro de los 45 s del turno.

## API

No cambia ninguna firma pública: `generar(peticion) -> RespuestaInferencia` sigue igual, y `FIRMAS_COMPUERTAS.json` no se toca.

**Configuración** (`config_inferencia.yaml`):
```yaml
reintentos: 1
espera_reintento_s: 1.0   # base; jitter de 0,5x a 1,5x
espera_maxima_s: 5.0      # si la espera calculada supera esto, no se reintenta
```

**Funciones privadas nuevas** en `inferencia_service.py`, para probarlas sin red:
```python
def _retry_after_s(exc: BaseException) -> float | None: ...
    # Segundos de Retry-After si vienen como número >= 0; None si no hay cabecera o es ilegible.

def _espera_reintento(exc: BaseException, base_s: float, aleatorio: Callable[[float, float], float] = random.uniform) -> float: ...
    # max(Retry-After, base_s * aleatorio(0.5, 1.5)).
```

## Reglas

- **R1. La base es 1,0 s con jitter.** Sin `Retry-After`, la espera es `espera_reintento_s × U(0,5; 1,5)`.
- **R2. Retry-After manda hacia arriba.** Con un `Retry-After` legible (un número ≥ 0 en segundos), la espera es `max(Retry-After, base con jitter)`. Una fecha HTTP, un texto o un número negativo se ignoran.
- **R3. Hay un tope.** Si la espera supera `espera_maxima_s`, no se duerme ni se reintenta: falla cerrado en el acto.
- **R4. Solo se reintenta si cabe.** Hace falta `restante − espera ≥ espera_reintento_s`. Si no se cumple, falla cerrado sin dormir.
- **R5. No cambia nada más.**
  - Sigue habiendo un solo reintento.
  - 400, 403 y 404 no se reintentan.
  - Un timeout sigue siendo `TiempoAgotado`.
  - El reintento vuelve a reservar cuota y conserva la primera reserva (Decisión 9).
  - El motivo de la falla sigue siendo `proveedor_no_disponible:<tipo>`.
- **R6. La configuración se valida.** `espera_maxima_s` es mayor que `espera_reintento_s`. Si no, `_validar_config` devuelve un motivo y la sala no está disponible, como pasa hoy con una config inválida.

## Interfaz

No aplica: no hay texto de cara al usuario. El huésped ve el mismo mensaje de degradación que hoy cuando la inferencia falla cerrada.

## Aceptación

Las pruebas usan `ErrorProveedor` con una `response` falsa cuando hace falta una cabecera, reemplazan `time.sleep` con monkeypatch para registrar las esperas, e inyectan el aleatorio.

| A2 | dados un aleatorio que devuelve su mínimo y otro que devuelve su máximo, entonces las esperas son exactamente 0,5 y 1,5 s | tests/inferencia/test_reintento_429.py::test_r1_jitter_entre_medio_y_uno_y_medio | m2: quitar el jitter (`aleatorio` constante en 1,0 dentro de la función) |
| A3 | dado `Retry-After: 3`, entonces se duerme 3 s | tests/inferencia/test_reintento_429.py::test_r2_retry_after_manda_hacia_arriba | m3: ignorar la cabecera |

**Rojo:** en el primer commit, los casos A1 a A3 y A5 a A9 de `test_reintento_429.py` fallan contra `c55c529` por `AssertionError`. A4 pasa como guarda: con un aleatorio inyectado y `Retry-After: 0`, la espera de hoy ya es la base con jitter, y el caso mata a m4 en el verde. Las pruebas obtienen `_retry_after_s` y `_espera_reintento` con `getattr(módulo, nombre, None)` y afirman que existen, en vez de fallar por `AttributeError`. El cambio a `test_paso4_adr0021.py` (solo reemplazar `time.sleep`) va en ese mismo commit, y esas pruebas quedan en verde.

**Verde:** pasan `tests/inferencia`, `tests/app_core/test_inferencia_con_tope.py` y `tests/test_firmas_compuertas.py`, la suite completa sin e2e no tiene fallos, y el arnés da Exit 0.

**Nota sobre m10 (corrección del 2026-11-25):** la mutación original, `range(reintentos + 2)`, resultó equivalente en el arreglo. La guarda explícita `if intento >= reintentos` corta antes de que el bucle llegue al tercer intento, así que ampliar el `range` no cambia la conducta. La mutación nueva actúa sobre el valor que limita los reintentos, sea cual sea la forma del bucle, y A10 la mata.
