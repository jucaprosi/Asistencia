## API

No cambia ninguna firma pública: `ObservabilidadService` y `FIRMAS_COMPUERTAS.json` siguen igual. Cambia una clase privada de la sala:

```python
class AlmacenTrazas:
    def __init__(self, db_path: Path | str | None = None, db_url: str = "") -> None: ...
        # db_path manda si viene (como hoy). Si no, abre envolver(db_url) cuando db_url es una URL resuelta;
        # vacía o con un placeholder sin resolver ("${"), SQLite en memoria. Nunca envolver(None).

class GestorTrazas:
    def __init__(self, config, almacen=None):
        self._almacen = almacen or AlmacenTrazas(db_path=config.get("db_path"), db_url=str(config.get("db_url") or ""))
```

## Reglas

- **R1. La sala solo lee su configuración.** `AlmacenTrazas` abre la base de `db_url` y no llama a `envolver(None)` ni lee `os.environ` (ADPA §2.4).
- **R2. Vacío o sin resolver es memoria.** Un `db_url` vacío, o uno que contiene `${`, abre SQLite en memoria. En producción `app_core` siempre lo resuelve, así que este caso solo aparece en pruebas que construyen la sala sin el pasillo.
- **R3. PostgreSQL inalcanzable falla cerrado.** Si `db_url` es PostgreSQL y no responde, no se cae a SQLite. Construir o reservar falla, o `reservar` devuelve False.
- **R4. Las pruebas no declaran un PostgreSQL falso.** Ningún archivo de `tests/` asigna un literal `postgres://` o `postgresql://` a la clave `DATABASE_URL`. Las pruebas que necesitan PostgreSQL lo toman de `TEST_DATABASE_URL` y llevan `requiere_pg`.
- **R5. Lo demás no cambia.** `db_path` explícito y `":memory:"` se comportan como hoy. En PostgreSQL, el esquema lo sigue aplicando `scripts/migrar_db.py`.
